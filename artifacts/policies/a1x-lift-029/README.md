# A1X + G1 lift policy: comparison package

Candidate **029** is an imitation policy for lifting a **30 mm, 30 g simulated
cube** more than 60 mm and maintaining bilateral contact for a full two seconds.
It runs through `PolicyRunner -> Twin -> SafetySupervisor -> SceneBackend`.
The evaluator independently checks the true object and contacts at every physics
step. A rejected motion is a failed attempt, even when it prevents a collision.

This package is for Marcin's **simulation comparison**. Physical execution and the
actual two-camera pipeline have not been validated by this task. Calibration-error
tests corrupt the pose delivered to the policy; they do not exercise camera images,
the detector, camera fusion, or the physical robot.

The earlier nominal reference passed 20/20 held-out lifts. Candidate 029 was
selected using development cases only, before the reserved calibration evaluation.
The matching publication code incorporates the team's `a1x-twin` changes through
`1ee666b` and reproduces all 60 candidate development outcomes and final controller
and physical states exactly. `manifest.json` binds the package to its source and
robot assets. Use this branch's controller with the checkpoint.

Validation also includes 195 focused checks, including 32 backend tests using an
in-memory CAN bus. Three actual PPO training cases were deliberately excluded.
`validation.json` records the test scope and SDK identity; none of these tests
establishes physical calibration or arm readiness.

The checkpoint and 16 conditions were frozen before the first use of seeds
52000-52019. All **320 trials** completed: **318/320 successes**,
**0 prohibited contacts**, **0 numerical faults**,
and **2 controller rejections**. These trials reuse 20 distinct starts across conditions.

| Rotation-vector jitter, 0.5 degree per-axis standard deviation | 20/20 |
| Requested 50 ms causal delay | 20/20 |

The predeclared threshold is at least 18/20 in every condition and zero prohibited
contacts/numerical faults: **passed**. Successful true holds span
2.080-2.440 seconds. 44,537 logged input frames were audited;
true starting states match across conditions and injected bias affects the supplied pose.
Actual delay was 60 ms for 1,414 non-warmup observations and 100 ms for 1,394,
due to simulation delivery timing.
Per-condition Wilson confidence intervals are in `calibration-heldout.json`.

The achieved tolerance applies only to the separately tested signed axes and error
magnitudes in this simulation. It is not a combined-error or physical tolerance.


Per-attempt outcomes are included in the JSON reports. Full observation/action
traces are regenerated by the evaluation commands below. Small fixed test sets
do not establish a population-wide reliability guarantee. Reusing published
qualification seeds is regression/comparison evidence, not a new held-out test.

## Run the comparison

Use a separate checkout of `codex/a1x-lift-comparison`. The verified environment
is Linux/WSL, Python 3.12, MuJoCo 3.14.0, NumPy 2.2.6 and PyTorch 2.11.0+cu126;
all policy evaluation and short fitting here ran on CPU. Install the repository's
`twin` extra with `constraints.txt` (install the desired PyTorch wheel first, as
described in the repository README). No GPU training is needed for these commands.

From the repository root:

```bash
python -m pip install -e '.[twin]' -c constraints.txt
python artifacts/policies/a1x-lift-029/verify.py

# Autonomous nominal comparison: identical starting seeds for both policies.
MUJOCO_GL=disable OMP_NUM_THREADS=2 python scripts/evaluate_a1x_runtime.py \
  artifacts/policies/a1x-lift-029/policy.pt \
  --out workspace/comparison/ours-nominal.json --seed 50000 --episodes 20

MUJOCO_GL=disable OMP_NUM_THREADS=2 python scripts/evaluate_a1x_runtime.py \
  /path/to/marcin-policy.pt \
  --out workspace/comparison/marcin-nominal.json --seed 50000 --episodes 20

# Persistent calibration errors, jitter and delay: 320 development trials.
MUJOCO_GL=disable OMP_NUM_THREADS=2 python scripts/evaluate_a1x_perception.py \
  artifacts/policies/a1x-lift-029/policy.pt \
  --out workspace/comparison/ours-perception --split development \
  --translation-mm 1 --rotation-deg .5 \
  --position-noise-mm 1 --rotation-noise-deg .5 --delay-ms 50 --seconds 600
```

## Input, action and completion contract

- 36 inputs: normalized measured and commanded joints (seven each), TCP position,
  perceived cube position, cube-relative-to-TCP position, two rotation columns,
  and the previous seven actions. Positions are in metres in the arm-base frame.
- `cube_yaw_mode=continuous`: nearest 90-degree-equivalent yaw across observations
  for an upright square cube; this is not arbitrary-object orientation tracking.
- Six arm actions are incremental joint commands, scaled by the saved task's
  0.05 rad step at 20 Hz. The gripper uses normalized absolute jaw targets.
- `gripper_decoder=a1x-templates-v1` chooses the nearest supported target from the
  learned output: open, 1 mm inward from measured jaw position, or fully closed.
  It does not call the teacher. Physical gripper endpoint/feedback agreement remains
  unverified. Preserve `features=a1x-alignment-v1` and its geometry hash.
- `cube_height_error_bound_m=0.005`: the controller requires perceived lift above
  65 mm before starting its two-second completion timer. The independent scorer
  still requires true lift above 60 mm. This allowance is not a 5 mm grasp tolerance.

## Before considering physical execution

The task has deferred physical-arm access and testing. Needed checks include
the actual two-camera pose/frame/timestamp contract, measured calibration errors
across the workspace, table/base/tool geometry, G1 measured feedback and timing,
and a supervised low-speed controller validation with an attending operator.
Adjacent physical work reported a model/table/tool clearance discrepancy; do not
treat simulated clearances as physical certification. This package contains no
automatic hardware launch or motor-command instructions.

The synthetic persistent-error model applies `p' = R_bias p + t_bias` and
`R' = R_bias R` in the arm-base frame. The transform stays fixed for an episode;
rotation changes both object position about the arm base and its orientation.
Jitter and causal delay are separate. Combined biases, larger errors, different
objects, lighting/detection failures, and real camera performance need separate
validation.
